# Snippet Command: Resume From the Plan File

> Type this into the agent chat after a compaction, a `/clear`, a crash, or an
> interrupted turn. Unlike a bare "continue", it rebuilds the state from the plan
> file, the diff, and the PR registry before doing anything.

---

Resume this session from its plan file. Read the plan's latest state, `git status`, the diff, and `bun scripts/pr-registry.mjs status`; if my last turn was interrupted, first find leftover processes by PID and reconcile partial edits. Continue from the last verified checkpoint. Do not replay finished work: a `[x]` alone does not justify skipping, a fresh `skip_if` run does. Do the next unchecked item, cite evidence when you check it, and tell me in one line where you resumed.

PROGRESS METER: whatever this trigger asks for, open every message to me in the chat that reports progress (a checkpoint, a phase change, a status or recap, the final report) with one meter line, as `sucp-rules` Progress Meter at Checkpoints defines it: `▰▰▰▱▱▱▱▱▱▱ 30% · 3/10 · <item in progress>`. Ten segments, `▰` filled and `▱` empty, then percent, `N/M` and the item in progress. Filled means `[x]` items (each already cites evidence) over all items in the plan file checklist, rounded down, so 100% appears only when every item is `[x]`. Always show `N/M`; when M grows, say `+1 item` instead of letting the bar look like a regression. During a debt sweep use one star per debt found instead (`★` closed with evidence, `☆` open, for example `★★★☆☆`). If there is no plan checklist yet, print no meter and never estimate a percentage. The meter is chat only: never written to a file, plan, progress log, handoff, PR body, commit message, or issue.

CONFIRMATIONS: every time you need a decision from me (an approval gate, a clarifying question, a risky action, a merge, a follow-up), call the harness's own question tool instead of writing the question in chat: `AskUserQuestion` in Claude Code, `question` in OpenCode, `ask_user` in Gemini CLI, or the equivalent you find by name. Show the artifact in chat first, then ask. Give 2 to 4 ready-made options, the recommended one first and labelled `(Recommended)`, so Enter accepts it; keep labels to five words or fewer, each with a one-line description. I do not want to type: never end a turn on a plain-text question, never open a text-only prompt, and never add an Other option the tool already provides. For destructive, hard-to-reverse, externally visible or shared-system actions (force push, delete, merge, publish, deploy, spend money, write to a global file) put the safe option first, with no `(Recommended)` tag, so a stray Enter cannot run the action, and ask it alone. At most 4 questions per call. A dismissed question is not an approval: a gate stays closed and the same question is not re-asked, while a clarifying question that is not a gate takes your recommended default and records it as an assumption. Unattended runs ask nothing mid-run: a reversible decision follows the Unattended Continuation Rule, and an irreversible one that could go either way is parked in the handoff with your recommended answer. If the runtime has no question tool, the tool errors, or no interactive client is attached, use a numbered list, say so, and keep the gate closed. Subagents never ask me; they report to you and you ask. `sucp-rules` Confirmation Protocol is the full rule.
