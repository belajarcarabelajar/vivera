# Snippet Orkestrasi: Overnight Run to a Pull Request

> Copy-paste the block below into the agent chat when an approved plan should be
> carried to a verified pull request while you are away. The run ends in a PR that
> waits for you. It never merges.
>
> This block is a **trigger prompt**: the agent reads it as an instruction, not a
> summary. The ENTRY GATE, the NEVER list, and the HANDOFF rules below are mandatory.
>
> `#{clipboard}` is substituted by Snipset at expansion time with whatever you
> copied. Copy the path of the approved plan file (or its plan issue URL). Anything
> else is a stop, see ENTRY GATE below.

---

Apply super-ultra-code-plan (fallback chain: ~/vivera/Super Ultra Code Plan Implementation.md, then ~/.agents/skills/super-ultra-code-plan/SKILL.md, then ~/.gemini/config/skills/super-ultra-code-plan/SKILL.md, then ~/.config/opencode/skills/super-ultra-code-plan/SKILL.md, then ~/.claude/skills/super-ultra-code-plan/SKILL.md, then ~/.config/ai/Super Ultra Code Plan Implementation.md; use the first file found and state which path was used). Load `sucp-rules`, `sucp-overnight`, `sucp-tdd-debug`, `sucp-verify-deliver`, and `sucp-debt-sweep` by name before the first mutation; if the skill tool cannot load them, read `~/vivera/skills/<name>/SKILL.md` and say so. I am leaving. Carry the plan below to a verified pull request without me.

PLAN: #{clipboard}

ENTRY GATE RUNS FIRST, BEFORE ANY WORK. The text above is the ONLY statement of what to run. Resolve it to one plan file and read it. Then check, in order: the plan says `status: Approved`; its approved scope names the pull request as the deliverable; `gh auth status` and `git fetch origin main` both succeed; the plan records any deadline, paid services allowed, and off-limits paths (absent means none). If any check fails, STOP and name the failed check. Do not write a file, do not claim a slot, and do not approve the plan yourself: approval cannot be collected while I sleep, so a Draft plan means I run brainstorm and plan first. A clipboard with no recognizable plan is a stop, never a guess at a nearby file.

THEN RUN THE PIPELINE AS WRITTEN, WITH NOBODY TO ASK. ISOLATION IS DERIVED: run `bun scripts/pr-registry.mjs claim --plan <plan-id> --session <session-slug>` and use the branch and worktree it prints, then `git worktree add` it beside the repository before anything is written. GIT WRITES ARE PARENT-ONLY: a subagent edits files and runs tests, and never runs git or `gh`. EXECUTION IS SUBAGENT-FIRST, MANDATORY, inside that worktree: TASK-CHUNKING into the smallest independently verifiable units; a BATCH MANIFEST written before dispatch (chunk id, owner, target files, expected output, verification command, one owner per file); a HIGH FAN-OUT FLOOR of 10 or more narrow subagents when the task supports it, in NON-OVERLAPPING workspaces, with NESTED FAN-OUT where a chunk still holds independent work; GATHER & SYNTHESIZE at a checkpoint, where reports are inputs and never conclusions; and a PARENT DIFF AUDIT GATE that re-runs the targeted tests in the parent before integrating. Write a per-chunk contract per templates/subagent-contract-template.md. Then TDD, local verification with exit codes, and the PR from templates/pull-request-template.md posted with `--body-file` and recorded with `bun scripts/pr-registry.mjs pr`. EVIDENCE for external facts is gathered with TinyFish per sucp-brainstorm: `search` to discover and `fetch_content` to read, both free; `run_web_automation` and browser sessions are metered, so they stay off unless the plan names them. KEEP THE TO-DO LIST IN THE PLAN FILE, each item checked only with its evidence. Follow `sucp-overnight` for everything specific to being unattended.

DECIDE WITHOUT ASKING, AND WRITE IT DOWN. Take the most reasonable reading, state it in one line, continue. Each such decision goes into the handoff with the alternative you rejected. A decision that is irreversible and could go either way is not made: prepare it, write the question and your recommended answer, park that chunk, and keep working on the independent ones. Ask no blocking question mid-run.

RETRY BUDGET. A red chunk gets at most 2 attempts, the second different from the first; the third failure marks it `blocked` with the failing command and exit code, and the rest continues. The same failure in two chunks means a shared cause: stop dispatching and investigate the contract first. Never make a red result green by skipping or deleting a test, loosening an assertion, using `--no-verify`, or editing a gate. Work that never reaches `verified` gets no pull request; leave the committed branch and worktree intact and say so.

NEVER, WHATEVER HAPPENS DURING THE NIGHT: merge into the base branch (the PR is the finish line), force-push any branch, deploy or publish anything, write outside the repository and its session worktree, delete state this session did not create, widen the approved scope, or use a paid service the plan does not name. If finishing the plan seems to need one of these, park it under `Waiting on a human` and stop that chunk.

CLOSE. Run the debt sweep (Step 6, sucp-debt-sweep) with one change: no follow-up executes unselected. Inject the multi-select question as the LAST act; if there is no structured question tool or no answer arrives, write every follow-up to the plan backlog with `defer: <ceiling>, <upgrade-trigger>` and treat the session as complete. Then write the handoff next to the plan as `<plan-id>-overnight-handoff.md`, containing Result, Evidence (each command with its exit code), Decisions, Blocked, Waiting on a human, and Undo. Your final message starts with the PR URL, or the word `none` and the reason. Run `graphify update .` first, then `bun run graphify:sync` from the vivera repository as the END-OF-SESSION GRAPH INDEX, and record in one line if graphify or `graphify-out/graph.json` is absent. Make sure to remember this skill while we are working in this session, and re-call it at every checkpoint.
