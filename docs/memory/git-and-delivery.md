# Git and delivery

> Part of the rule handbook indexed in [MEMORY.md](../../MEMORY.md). Rule IDs are global and never reused.

| # | Rule (`WHEN <situation> → DO <action>, NOT <anti-pattern>`) | Origin session |
|---|---|---|
| L8 | WHEN running repo tooling that owns a state file (pr-registry, plan issue sync) → DO run it from the checkout that owns the state file, NOT from a session worktree (gitignored state does not propagate to worktrees) | open-source-sanitize (PR #6) |
| L16 | WHEN `git pull` reports untracked files would be overwritten → DO verify each untracked file is already present in `origin/main` with `git show origin/main:<path> \| diff -q - <path>`, THEN remove and pull, NOT `git clean -fd` (the session's own new files are exactly the ones that block the pull after their PR merges) | PR #15 merge |
| L17 | WHEN a required reviewer blocks a merge → DO check that the approver CAN exist before offering any path that depends on them (`gh api repos/O/R/collaborators --jq length`, then a dry `gh pr review --approve`), NOT stop and wait (measured on PR #18: `mergeStateStatus: BLOCKED`, `required_approving_review_count: 1`, and the repo had exactly 1 collaborator who was also the sole CODEOWNER, so the review was unsatisfiable by anyone) | unprefixed-branch-names (PR #18) |
| L18 | WHEN a required approval is structurally unsatisfiable → DO say so and name the cheapest non-destructive bypass, NOT list waiting as one of the options (measured: `gh pr merge --admin` merged in one call and left `required_approving_review_count: 1`, `require_code_owner_reviews: true`, and `bypass: []` unchanged; PRs #12 to #17 had all merged the same way, which is the check I should have run first) | unprefixed-branch-names (PR #18) |
| L19 | WHEN a pr-registry row names a PR number or a worktree path → DO resolve the owning repository from the row itself before calling `gh pr view`, NOT assume the current checkout owns it (measured: `gh pr view 458` from the vivera checkout returned `Could not resolve to a PullRequest`, and the PR was Snipset's, so trusting the first result would have recorded a merge against the wrong repository) | unprefixed-branch-names (PR #18) |
| L21 | WHEN a merge is blocked and the blocker is a required review → DO run the L17 collaborator check and the L18 remedy in the SAME turn, NOT present waiting as an option alongside them (measured on PR #24: `--admin` was available, used, and the user is the sole CODEOWNER who has to authorise it, so "wait for a reviewer" handed back a decision that was already theirs to make) | loop-convergence (PR #24) |
| L22 | WHEN the repository owner merges their own PR directly (web UI, `--admin`, or protection at 0) → DO treat it as normal delivery, NOT record it as a bypass, defect, or finding (measured: this repo's owner is admin + sole CODEOWNER + only collaborator; no other approver can exist, so their direct merge IS the delivery mechanism, and flagging it wastes a turn every PR) | owner-merge policy (PR #24-29) |
| L25 | WHEN a repo's plan tooling is configured under a key differing from its directory name → DO pass `--project <key>`, NOT assume the directory name resolves (measured: `plan-issue-sync` refused with `no GitHub repository is configured for project "vivera"` because `plan.issues.json` maps this repo under `ai-skills`; the error names the key, so read it rather than editing the config) | quadrant-fill-contrast |
| L28 | WHEN checking whether a plan's vault mirror is current → DO run `bun scripts/plan-publish.mjs --check <plan>`, NOT `ultra-plan-runner.mjs <plan> --execute` (measured: `--execute` runs the whole task DAG in the current directory; it stopped at the `files` precondition only because of a plan defect) | claude-code-agents (PR #42) |
